# RealDeal — focused buy/sell MVP

Team JDI, JigJoy AI Hackathon. Internal deadline November 27, 2026 at 16:00 CET; demonstration at 17:00 CET.

Answer one question: **Given what I own, what I want, and my cash, what is the best feasible combination of buying, selling and waiting?**

The default web screen combines a goal, budget, reserve, desired purchases, owned assets, conditional resale and current strategy. All transactions are simulated. Keep the original Serbian search, budget and resale tools and Telegram bot operational. Avoid a full marketplace, autonomous spending, speculative flipping or unsupported financial claims.

Financial arithmetic and transaction guards belong in deterministic code. LLMs explain evidence and tradeoffs. Estimated sale proceeds are not spendable until a simulated net receipt is confirmed. Always account for explicit fees, delivery, condition, warranty, risk and liquidity. Defer purchases instead of borrowing or creating a negative balance.

The financial agents use native Mozaik 6.0.0 runLoop calls on a typed shared runtime, independent asynchronous I/O, optional concurrent model requests, revision checks and interception of obsolete transitions. Show actual execution intervals. Offline analysis must never be described as live LLM inference.

Use synthetic data for the reproducible scenario. Keep live adapters opt-in and respect existing access restrictions. No listings, real orders, payments or external messages are authorized by app controls.

Read README.md for operation, demonstration, architecture and limitations. docs/PIVOT_PROMPT.md is historical context for the earlier search pivot, not the current implementation specification.
